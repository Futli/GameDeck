# Telegram Mini App: разбор по шагам

Как GameDeck понимает, что его открыли в Telegram, и почему серверу можно верить, что игрок — именно тот, за кого себя выдаёт.

## Шаг 0. Что получится

- Игрок открывает бота и жмёт кнопку меню. Игра открывается внутри Telegram.
- Имя вводить не нужно: имя и аватар берутся из Telegram. Один Telegram-аккаунт — один профиль с монетами и рейтингом, с любого устройства.
- Цвета подстраиваются под тему Telegram (светлую или тёмную). Сукно стола остаётся зелёным.
- Кнопка с кодом комнаты открывает «Поделиться» Telegram со ссылкой `https://t.me/<бот>/play?startapp=K7M2Q`. Друг жмёт ссылку и сразу садится за стол.
- В обычном браузере всё работает как раньше: анонимный вход по токену и ввод имени.

## Шаг 1. Что такое initData

Когда Telegram открывает Mini App, он передаёт странице строку `initData`:

```
query_id=AAE…&user={"id":7300243,"first_name":"Лёха","photo_url":"…"}&auth_date=1793430000&start_param=K7M2Q&hash=9f3c…
```

Скрипт `telegram-web-app.js` (подключён в `packages/client/index.html`) кладёт её в `window.Telegram.WebApp.initData`. Там же лежит разобранная копия `initDataUnsafe`. Её клиент использует только для показа: имя в лобби и код комнаты из `start_param`.

Главное: **клиенту верить нельзя**. Любой может открыть сайт в браузере и подставить в `initData` чужой `id`. Поэтому клиент не разбирает строку, а целиком отправляет её серверу при подключении сокета (`handshake.auth.initData`, `packages/client/src/lib/socket.ts`).

## Шаг 2. Проверка подписи на сервере

Поле `hash` — это HMAC-подпись остальных полей. Подписать их может только тот, кто знает токен бота: Telegram и наш сервер. Алгоритм из документации Telegram (`packages/server/src/telegram/init-data.ts`):

```
data_check_string = все поля, кроме hash, по алфавиту, "key=value" через \n
secret            = HMAC_SHA256(key = "WebAppData", data = BOT_TOKEN)
hash              = hex(HMAC_SHA256(key = secret, data = data_check_string))
```

Ещё три детали, о которых спрашивают на собеседованиях:

- **Сравнение за постоянное время** (`timingSafeEqual`). Обычное `===` останавливается на первом несовпавшем байте, и по времени ответа можно подбирать подпись побайтно.
- **Срок жизни** (`auth_date`). Украденная строка через сутки уже не пустит. Срок задаёт `TELEGRAM_INIT_DATA_MAX_AGE`.
- **Сервер не ходит в api.telegram.org.** Проверка — чистая математика с токеном. Поэтому блокировки Telegram API на сервере в РФ входу не мешают.

Не та подпись — сокет получает `connect_error` с `TELEGRAM_AUTH_FAILED`, и клиент просит перезапустить игру.

## Шаг 3. Кто этот игрок

`PlayerService.resolveTelegram` (`packages/server/src/players/player-service.ts`) ищет игрока по `players.telegram_id`:

1. Нашёлся — обновляем имя и аватар (их могли поменять в Telegram), выдаём сессию.
2. Не нашёлся, но у клиента есть токен анонимного игрока — **привязываем** Telegram к нему. Монеты и рейтинг, набранные до входа через Telegram, не теряются. Игрока, уже привязанного к другому Telegram, перепривязать нельзя.
3. Иначе — новый игрок со стартовыми монетами.

Дальше всё как раньше: `socket.data.playerId`, сессия, комнаты. Аватар (`players.avatar_url`, миграция `drizzle/0001_telegram_avatar.sql`) едет в `PlayerView.avatarUrl` и рисуется у имени за столом.

## Шаг 4. Тема и поведение окна

`initTelegram()` в `packages/client/src/lib/telegram.ts` вызывается до рендера React:

- `themeParams` → CSS-переменные (`--bg`, `--text`, `--accent`…), на `themeChanged` — заново;
- `expand()` — на всю высоту;
- `disableVerticalSwipes()` — свайп по столу не закрывает игру;
- `ready()` — Telegram убирает заставку загрузки.

## Шаг 5. Настройка

В `deploy/.env` на сервере:

```
BOT_TOKEN=123456789:AA…        # от @BotFather, никому не показывать и не коммитить
TELEGRAM_APP_URL=https://t.me/<бот>/play
```

`docker compose up -d` перезапустит приложение с новыми переменными. Проверить, что адрес дошёл до клиента: `curl https://<домен>/api/config`.

Без `BOT_TOKEN` вход через Telegram выключен: initData игнорируется, игроки входят анонимно. Без `TELEGRAM_APP_URL` приглашения ведут на сайт (`/?room=КОД`).

## Шаг 6. Как это проверено

- `packages/server/test/telegram.test.ts`: правильная подпись, подделанные поля, чужой бот, устаревшая строка; один Telegram id — один профиль; привязка анонимного игрока; отказ сокету с поддельной initData.
- Вручную в Chromium со «встроенным» Telegram (подменённый `telegram-web-app.js` с подписанной initData): лобби без ввода имени, светлая тема, автоматический вход по `startapp`, ссылка «Поделиться».

Локально без Telegram можно подписать свою initData функцией `signInitData` из `init-data.ts` тем же токеном, что в `BOT_TOKEN`.

# Git и pull requests

- **Не коммитить в `main`.** Ветка создаётся до первой правки.
- **Параллельно идут несколько веток и сессий.** Перед работой и перед пушем — `git fetch origin main`
  и слить main в свою ветку. Конфликт решается так, чтобы не потерять чужие изменения. Хук SessionStart
  сам сообщает, отстала ли ветка.
- **Один PR на одну работу.** Доработки идут в ту же ветку, описание PR переписывается. Второй PR поверх
  открытого не делается. Если PR уже смержен — новая ветка от свежего main и новый PR.
- **Заголовок PR — `type(scope): описание`**, по-русски после двоеточия. Типы и scope — закрытые списки
  в `.github/pr-title.json`, проверка — workflow `PR title`. Новый scope добавляется в этот файл в том же PR.
  Локально: `node .github/scripts/pr-title.mjs "feat(perudo): ставка «точно»"`.
- **Коммиты** — по-английски, в повелительном наклонении.
- **В диффе только само изменение.** Перед коммитом `git diff` показывает столько строк, сколько нужно
  задаче. Форматирование чужого кода — отдельным PR.
- **Описание PR по-русски:** что сделано, как проверено, что осталось.

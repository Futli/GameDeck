# Код

Правила кода, которые не проверяет ни один инструмент. Всё, что может проверить программа,
живёт в проверке (ESLint, Prettier, knip, TypeScript, CI), а не здесь.

- **Комментарии и тексты по-русски.** Комментарии, документация, тексты UI. Код учебный, поэтому
  комментарий объясняет «зачем», а не пересказывает строку.
- **Новая игра:** файл в `packages/shared/src/games/`, строка в реестре `games/index.ts`, тесты
  в `packages/shared/test/` с детерминированным `rng`. Если в игре есть скрытая информация — `viewFor`
  и сквозной тест, что чужие данные не приходят клиенту.
- **Протокол меняется везде сразу.** Новое или изменённое событие описывается в `shared/src/protocol.ts`
  и `schemas.ts`, а сервер и клиент правятся в том же PR. Без фолбэков «для старого клиента».
- **Невалидное значение не превращается в дефолт.** Сломанный ввод отклоняется ошибкой с `code`,
  а не подменяется нулём или пустой строкой.
- **Монеты** меняются только через `changeCoins` (`server/src/db/wallet.ts`), с записью в журнал.
- **Схема БД:** после правки `server/src/db/schema.ts` — `pnpm db:generate` и закоммитить миграцию.
- **Тесты по сложности.** Правила игр и рейтинг покрыты юнит-тестами; сценарий комнаты с несколькими
  игроками — сквозным тестом по образцу `server/test/socket.test.ts` (настоящий сервер на порту 0,
  несколько `socket.io-client`). Перекладывание полей и то, что гарантируют типы, тестов не требует.
- **Мок не проверяет границу, которую подменяет.** Для БД в тестах используется настоящий PGlite в памяти,
  а не мок.

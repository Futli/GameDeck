# Клиент GameDeck: разбор по шагам

Продолжение [server-guide.md](server-guide.md) и [database-guide.md](database-guide.md). Клиент: Vite + React + чистый CSS, лежит в `packages/client`.

## Шаг 1. Зачем Vite и как клиент находит сервер

Vite — сборщик и dev-сервер. В разработке он отдаёт страницу на порту 5173 и мгновенно применяет правки (hot reload). Для продакшена `vite build` собирает всё в `packages/client/dist`: один HTML, один JS, один CSS.

Сервер и клиент в разработке живут на разных портах, но браузер этого не замечает благодаря прокси в `vite.config.ts`:

```ts
proxy: {
  '/api': 'http://localhost:3000',
  '/socket.io': { target: 'http://localhost:3000', ws: true },  // ws: true — пробрасывать и WebSocket
},
```

Поэтому в коде клиента нет ни одного адреса сервера: `io()` подключается к тому же origin, откуда открыта страница. В продакшене это сервер на 3000, в разработке Vite на 5173, который пересылает запросы на 3000.

Запуск обоих сразу:

```bash
pnpm dev   # сервер :3000 и клиент :5173 параллельно
```

С телефона через Tailscale: `http://<ip TRASHCAN>:5173` в разработке или `:3000` после `pnpm build && pnpm start`.

## Шаг 2. Сервер отдаёт собранный клиент (`server/src/http/client.ts`)

В продакшене нет Vite, поэтому страницу отдаёт сам Fastify через `@fastify/static`:

```ts
await app.register(fastifyStatic, { root: clientDir });
app.setNotFoundHandler((request, reply) => {
  if (request.method === 'GET' && !request.url.startsWith('/api/')) return reply.sendFile('index.html');
  return reply.code(404).send({ error: 'NOT_FOUND' });
});
```

Второй обработчик нужен для ссылок вида `/?room=K7M2Q` и будущих маршрутов: любой неизвестный адрес получает `index.html`, а дальше разбирается React. Один порт для страницы, API и WebSocket — так же будет и в Telegram Mini App.

## Шаг 3. Одно соединение на всё приложение (`src/lib/socket.ts`)

```ts
export const socket = io({
  auth: (cb) => cb({ token: localStorage.getItem('gamedeck.token') }),
});

socket.on('session', ({ token, playerId }) => {
  localStorage.setItem('gamedeck.token', token);
  setState({ playerId });
});
socket.on('room:state', (room) => setState({ room }));
```

- `auth` передан **функцией**, а не объектом. Socket.IO вызывает её при каждом переподключении, поэтому после обрыва связи на сервер уйдёт актуальный токен, и сервер вернёт игрока в комнату.
- Токен лежит в `localStorage`, поэтому перезагрузка вкладки не выкидывает из игры.

Все действия собраны в объект `api`:

```ts
export const api = {
  createRoom: (input) => call<RoomView>('room:create', input),
  roll: () => call<RoomView>('game:move', { type: 'roll' }),
  // ...
};
```

`call` отправляет событие с ack, ждёт ответ и при ошибке показывает текст сервера внизу экрана. Компоненты пишут просто `api.roll()` и не знают, как называются события.

## Шаг 4. Состояние без библиотек (`src/lib/store.ts`)

Клиенту нужно хранить совсем немного: подключены ли мы, кто мы, последний `RoomView` и итог партии. Redux или Zustand тут лишние. Хватает объекта и встроенного в React `useSyncExternalStore`:

```ts
const room = useClientState((s) => s.room);
```

Компонент перерисовывается, только когда меняется выбранная им часть. Главная мысль: **клиент не считает игру сам**. Он показывает последнее, что прислал сервер. Поэтому рассинхрона между игроками не бывает: у всех один и тот же `RoomView`.

## Шаг 5. Главная и экраны вне комнаты (`components/Lobby.tsx`)

Вне комнаты игрок ходит по экранам. Это не роутер, а состояние `screen` в `Lobby`:

| Экран                      | Что на нём                                                                    |
| -------------------------- | ----------------------------------------------------------------------------- |
| Главная                    | «Кубик удачи», баланс монет, карточки игр с рейтингом игрока в каждой         |
| Игра (`GameScreen`)        | Создать комнату (пароль по желанию), открытые комнаты этой игры, вход по коду |
| Настройки                  | Имя за столом и язык (`SettingsScreen`, вход — шестерёнка справа вверху)      |
| Мои скины, Статистика      | Иконки справа вверху главной (`SkinsScreen`, `StatsScreen`)                   |
| Кубик удачи (`LuckScreen`) | Призы и правила; сюда ведёт «Подробнее» из окна приза                         |

- **Виджет на главной** (`LuckWidget.tsx`) — тот же HTML, что бот присылает в чат, без копии разметки.
  Клиент берёт его с `GET /api/me/widget?lang=…` и вставляет во фрейм-песочницу (`sandbox="allow-scripts"`).
  Перед HTML стоит маленький мост: он подменяет `window.TelegramWidget`, и запрос броска вместо бота уходит
  родительскому окну через `postMessage`, а оно спрашивает `POST /api/me/widget/query`. Ответ и новое
  состояние (`chatData`) возвращаются во фрейм тем же путём. Фрейм сам сообщает свою высоту.
- **Имя** живёт в `lib/name.ts`: в Telegram — ник из Telegram, иначе последнее введённое в браузере;
  пришедший профиль подставляет имя с сервера, если игрок его ещё не правил. Без имени экран игры
  показывает поле имени прямо над кнопкой «Создать комнату».
- **Рейтинг** у каждой игры свой, поэтому стоит на карточке игры, а не одной цифрой.
- **Комнаты с паролем** сервер в список не присылает. Вход по коду сначала спрашивает
  `GET /api/rooms/:code`: есть пароль — появляется поле пароля, нет — сразу `room:join`.
- **Ссылка-приглашение** сразу сажает за стол (когда пришёл профиль): `startapp=КОД_реф_пароль`
  в Telegram (пароль hex-байтами UTF-8: в `startapp` можно только буквы, цифры, `_` и `-`) или
  `/?room=КОД&ref=…&pw=…` в браузере. Пароль в ссылку кладёт `RoomScreen` из `RoomView.invitePassword`:
  его сервер отдаёт только тем, кто уже сидит в комнате. Старые ссылки без пароля работают как раньше;
  если войти сразу нельзя (нет имени или пароля), открывается экран игры с вписанным кодом.
- **Отступы Telegram.** В полноэкранном режиме поверх приложения стоят кнопки Telegram («Закрыть», меню).
  `initTelegram` кладёт `safeAreaInset + contentSafeAreaInset` в CSS-переменные `--safe-*`, и `.app`
  отодвигает на них всё содержимое — на всех экранах сразу.
- «Мои скины»: вкладка на каждый предмет стола (коврик, кубики, стакан). Нажатие надевает скин
  (`POST /api/skins/:id/equip`), «Стандартный» снимает (`POST /api/me/skins/unequip`).
- «Статистика»: итоги и текущий рейтинг по каждой игре из `/api/me` (поле `ratings`), история партий
  из `/api/me/matches` с кнопкой «Показать ещё».

## Шаг 6. Стол под число игроков (`components/Table.tsx`, `lib/table.ts`)

Сервер сажает игроков на места 0..5. Пустых мест на столе не рисуем: раскладка зависит от того,
сколько людей в комнате, а каждый клиент поворачивает стол так, чтобы свой коврик был снизу.

```ts
const LAYOUTS = {
  2: ['bottom', 'top'], // друг напротив друга, стол уже
  3: ['bottom', 'left', 'right'],
  4: ['bottom', 'left', 'top', 'right'], // по одному с каждой стороны
  5: ['bottom', 'left-low', 'left-high', 'right-high', 'right-low'],
  6: ['bottom', 'left-low', 'left-high', 'top', 'right-high', 'right-low'],
};
```

`seatLayout(players, myId)` сортирует игроков по месту, сдвигает список так, чтобы зритель был первым,
и раздаёт позиции по часовой стрелке. Порядок за столом у всех одинаковый, меняется только точка обзора.

Размер стола — класс `table--duel` (1–2 игрока, одна колонка, стол уже и ниже), `table--cross` (3–4,
по одному месту на боку) или `table--full` (5–6, по два на боку). Это CSS Grid с именованными областями:

```css
grid-template-areas:                 /* full */
  '.    top    .'
  'lh   mid    rh'
  'll   mid    rl'
  '.    bottom .';
```

Позиция места — просто класс `seat--left-low` и т.п. На боковых местах коврик стоит вертикально (96×128), длинной стороной вдоль края стола.

Объём сделан «пиксельными» тенями без размытия: у коврика светлый край сверху-слева, тёмный снизу-справа и жёсткая тень под ним. Для этого у каждого цвета игрока три тона (`light`, `main`, `shade` в `PLAYER_COLOR_HEX`). Стол — насыщенное сукно с затемнением к краям и деревянный бортик.

Что видно на столе:

- **Коврик** 128×96 с пиксельным узором в цвете игрока (`player.color` приходит с сервера, оттенки из `PLAYER_COLOR_HEX`). Позже узор заменят спрайты скинов из магазина.
- **Кубик** на коврике: бросок текущего раунда, а между раундами — прошлого.
- **Подсветка**: жёлтая пульсация у того, чей ход; зелёная у победителя; серый коврик у выбывших из переброса; полупрозрачный игрок — офлайн.
- **Изменение рейтинга** `+16 / −16` рядом с именем, когда приходит `match:recorded`.
- **Центр стола**: название игры, «Ждём игроков 2/6», «Ходит: Боб», «Переброс, раунд 2», победитель, ставка.
  Номер раунда — табличка в золотой рамке со своими цветами, а не `--accent`: в Telegram тот бывает синим и не читается на сукне.

Стол не знает правил игры: он показывает `currentPlayerId`, `winnerId` и броски из состояния. Для новой игры понадобится только своя «центральная» часть и своё отображение на коврике.

### Кубик (`components/Die.tsx`, `shared/src/dice-style.ts`)

Кубик — пиксельная SVG-картинка на сетке 21×21. Сетка нечётная, поэтому у грани есть центральный пиксель, и точки встают строго симметрично:

```
пиксели точек по каждой оси: 5, 10, 15   (точка 3×3, от края грани 3 пикселя, между точками 2)

схема точек в ячейках 3×3 (колонка, ряд), как на настоящем кубике:
1: (1,1)          4: четыре угла
2: (0,0) (2,2)    5: четыре угла + центр
3: диагональ      6: две колонки по три
```

Схема лежит в `DICE_PIP_LAYOUT` в общем пакете, тест проверяет, что каждая раскладка симметрична относительно центра.

Скин задаётся двумя цветами:

```ts
<Die value={4} style={{ face: '#d91e2b', pips: '#ffffff' }} />
```

Обводку, блик сверху-слева и тень снизу-справа компонент вычисляет сам, смешивая цвет грани с чёрным и белым. Поэтому новый скин — это одна строчка в каталоге магазина (`server/src/shop/catalog.ts`):

```ts
{ id: 'dice-night', kind: 'dice', name: 'Ночь', priceCoins: 2500, asset: dice('#1b1f3a', '#7df9ff') },
```

Надетый скин (слот `dice`) сервер подставляет в `PlayerView.dice`, когда игрок входит в комнату, и все за столом видят кубики этого игрока в его цветах.

## Шаг 7. Комната и права хоста (`components/RoomScreen.tsx`, `HostPanel.tsx`)

- Кнопка с кодом копирует ссылку-приглашение. В ссылке реферальный код игрока: новичок, пришедший по ней, засчитается ему как приглашённый друг (см. docs/widget-guide.md).
- «Бросить кубик» видна только тому, чей ход. Сервер всё равно проверит очередь, кнопка — просто удобство.
- Хост в лобби видит «Начать игру», крестики для исключения игроков и настройки: лимит мест, ставку, пароль.
- Поток партии — всплывающие окна снизу (`components/modals/`), стол над ними остаётся виден. `ReadyCheckModal` — комната ожидания перед партией и после неё: кто уже ответил, таймер, «Играю» / «Выйти»; после партии — победа с конфетти или поражение, монеты. `RollModal` — начало раунда перудо: итог прошлого раунда, стакан трясётся как в виджете, кубики выпадают. `TimerBar` рисует оставшееся время по `msLeft` из состояния (хук `lib/countdown.ts`).

Права проверяет сервер. Если кто-то вручную отправит `game:start`, не будучи хостом, сервер ответит `NOT_HOST`. Клиент лишь не показывает лишние кнопки.

## Шаг 8. Стили (`src/styles.css`)

Чистый CSS, без фреймворков. Все цвета — переменные в `:root`:

```css
:root { --bg: #14161a; --accent: #f2b33d; --felt: #1f4d3a; ... }
```

Когда подключим Telegram Mini App, эти переменные заменятся цветами темы пользователя из `Telegram.WebApp.themeParams`, и приложение будет выглядеть «родным» в светлой и тёмной теме.

## Шаг 8½. Языки интерфейса (`src/i18n/`)

Все тексты, которые видит игрок, лежат в словарях, а не в компонентах:

- `i18n/ru.ts` — образец. Из него выводится тип `Messages`.
- `i18n/en.ts` объявлен как `const en: Messages`, поэтому забытый или лишний перевод — ошибка TypeScript, `pnpm check` её поймает.
- Тексты с числами — функции: `t.perudo.diceOnTable(10)` → «На столе 10 куб.» / «10 dice on the table». Склонения в языках разные (1 кубик, 2 кубика, 5 кубиков против 1 die, 2 dice), поэтому фразу целиком собирает словарь, а компонент только передаёт числа.

В компоненте:

```tsx
const t = useT();
return <button>{t.lobby.create}</button>;
```

Вне React (уведомления в `socket.ts`) — функция `t()`. Свой словарь у отдельной части (например, у обучения) — `Record<Lang, …>` и хук `useLang()`, чтобы выбрать нужный.

Язык при первом запуске берётся из Telegram (`initDataUnsafe.user.language_code`), в браузере — из `navigator.language`: ru/uk/be/kk получают русский, остальные английский. Переключатель RU / EN на странице настроек (`LanguageSwitch.tsx`) запоминает выбор в `localStorage` и меняет `<html lang>`.

Ошибки сервера приходят по-русски вместе с кодом (`{ code: 'ROOM_FULL', message: 'Комната заполнена' }`). На русском показывается текст сервера (он точнее: «нужно минимум 3 игрока»), на английском — перевод по коду из `enErrors` в `en.ts`. Новый код ошибки на сервере — новая строка в `enErrors`, иначе англоязычный игрок увидит общее «Something went wrong».

## Шаг 8¾. Обучение для новичков (`components/tutorial/`, `lib/tutorial.ts`)

Новичку правила объясняются прямо за столом, по ходу партии.

- **Что показать, решает чистая функция** `relevantTips(room, myId)` в `tutorial/tips.ts`. Она смотрит на тот же `RoomView`, что прислал сервер: лобби, начало партии, свой или чужой ход, вскрытие, мапуто, выбывание, конец. Возвращает список подсказок по важности, `pickTip` берёт первую непрочитанную. Своей копии игры у обучения нет, поэтому разойтись с сервером оно не может. Функция покрыта тестом `packages/client/test/tutorial.test.ts`, вид для теста строит настоящий `perudo.viewFor`.
- **Карточка `Coach`** стоит над кнопками хода и показывает одну подсказку. «Понятно» закрывает её навсегда, следующая появится, когда наступит её ситуация. «Выключить обучение» убирает и карточку, и подписи.
- **Подписи `Hint`** под каждой кнопкой (номинал, − и +, «Ставка», «Не верю!», «Точно!», «Начать игру», выход, код комнаты) говорят, что сделает кнопка. Видны, только пока обучение включено.
- **Кто новичок.** Обучение включается само, если в профиле `gamesPlayed === 0`, и это сразу запоминается, чтобы после первой партии оно не выключилось на полуслове. Кнопка «?» в шапке включает его заново (все подсказки покажутся снова) или выключает. Выбор и прочитанные подсказки лежат в `localStorage`: это личная настройка интерфейса, серверу она не нужна.
- **Тексты** все в `tutorial/texts.ts`: `Record<Lang, Dictionary>` с `ru` и `en`, компоненты выбирают словарь через `useLang()` из шага 8½. Забытый перевод — ошибка TypeScript.
